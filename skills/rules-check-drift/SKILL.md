# /rules-check-drift —— 让规则文件保持真实，而不是更长

你的规则文件——**`CLAUDE.md`** 或 **`AGENTS.md`**——是**指路文档，不是文档库**：里面是你的基本规则、约定，以及一份当前的**"东西都在哪里"地图**。它唯一需要担心的失败模式是**出错**：一条过时的规则或一张漂移的地图，会在未来每一次运行中主动误导 AI 助手。本技能对照刚发生的变化检查规则文件，并提出让规则保持真实所需的**最小**编辑。

> **错误的规则比缺失的规则更糟。更长的规则文件比精简的规则文件更糟。** 大多数变化根本*不需要*任何编辑——添加一行错误或啰嗦的内容会让它更糟。

## 输入
- `$ARGUMENTS` —— 可选的 diff 范围。默认：未提交 + 已暂存（`git diff HEAD`）；回退到 `main...HEAD`。
- **范围：项目的规则文件** —— `CLAUDE.md` 和/或 `AGENTS.md`，根级文件 + 任何包级文件。（如果 `CLAUDE.md` 只是 `@AGENTS.md` 导入，检查 `AGENTS.md`。）忽略 README、`docs/` 和 `.claude/`、`.qoder/` 的 agent/command/skill 文件。本技能的存在只为让*规则*保持诚实，别无其他。

## 流程

### 1. 看看改了什么
`git diff <range>` + `git status`。注意：移动/重命名/删除的文件、新模块、变化的约定，以及变化建立起来的任何新不变量。

### 2. 读取规则文件的当前状态
加载项目的规则文件——`CLAUDE.md` 或 `AGENTS.md`（以及任何包级文件）。把每一条主张与变更集对照。

### 3. 只标记这三类东西
1. **一条已陈述的规则或事实现在失真了** —— 例如"路由住在 `src/routes/`"但它们搬走了。→ 修复它。
2. **架构地图漂移了** —— 一个路径或"东西在哪里"的指针不再匹配现实。→ 修复错误的条目（不要给每个新文件编目录）。
3. **一个必须长期成立的新持久不变量** —— 变化引入了必须保持为真的规则（例如"绝不在 handler 里直接调用数据库——必须经过 `repository/`"）。→ 用**一行**添加它。

其他一切，都别动。**不要**为了*记录添加了某个功能*而建议编辑（那是变更日志的事——代码库才是事实来源），不要重述代码里已经显而易见的东西，也不要添加不指引未来工作的背景/理由/散文。

### 4. 把每条建议写成 CLAUDE.md 应有的样子
- **一条要点，不是一段话。** 规则是一行，不是一篇论文。
- **让地图保持最新——不要扩大它。** 修正错误的路径；不要枚举新路径。
- **用自然语言陈述规则；引用代码库，绝不粘贴代码。** 复制的代码会过时；代码库保持真实。好："遵循 `src/core/errors/` 里的错误模式。"坏：粘贴整个类。

## 输出
```
## 规则文件漂移检查 —— 范围：<range>

### 修复（现在失真了）
| 位置 | 哪里错了 | 最小修复 |
|-------|--------------|-------------|
| "架构"地图 | 路由从 `src/routes/` 移到 `src/api/routes/` | 更新这一个路径 |

### 添加（仅限新不变量）
- <一行规则> —— 由 <使其持久的变化> 确立

### 已检查，仍然为真 —— 无需编辑
- <你验证过不需要改动的区域>
```
如果什么都没漂移：**"规则文件对这些更改仍然准确——无需编辑。"**

## 规则
- **咨询性。** 报告漂移；只在调用者明确要求时才应用编辑 / piv-commit。
- **仅限规则文件**（`CLAUDE.md` / `AGENTS.md`）。不是 README，不是文档。
- **默认精简。** 拿不准时，建议什么都不做。
- **每次合并前运行它**（或作为 `/piv-review-changes` 的一部分），这样你的规则永远不会落后于代码。
