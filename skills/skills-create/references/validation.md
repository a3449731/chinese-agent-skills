# 验证门（Validation Gates）

创建或重构技能后跑这些。宣布完成之前修复失败。

## 门 1 — 结构
- `SKILL.md` 存在，且有以 `---` 分隔的有效 YAML frontmatter。
- Frontmatter 有 `name`（与目录匹配，lowercase-hyphen，≤64）和 `description`（≤1024，非空）。
- 正文里引用的每个文件都真实存在（没有死指针）。
```bash
# 个人技能库；团队共享改放项目级 .qoder/skills/
ls -R ~/.qoder-cn/skills/<name>
grep -nE '`(references|templates|scripts|assets)/' ~/.qoder-cn/skills/<name>/SKILL.md
```

## 门 2 — 描述质量（触发器）
- 第三人称；不是 "Use this when you…"。
- 说明它做什么**以及**何时用它。
- 包含用户真的会说的字面触发器短语，加上 `/name` 调用。

## 门 3 — 正文风格与大小
- 通篇祈使 / 不定式语态；没有第二人称（"you should"）。
- 正文是决策主干 + 指针，不是数据倾倒。
- 目标 1,500–2,000 词；超过约 5k 要调查。

## 门 4 — 渐进披露
- 笨重 / 偶尔需要 / 输出形状化的细节活在 `references/` 或 `templates/` 里（或被路径/URL 引用，或运行时收集）——不内联。
- 正文和资源之间没有重复内容。
- 总是需要的输出格式有**必读**指针；有时需要的细节有惰性指针。
- References 一层深，全部从 Resources 章节链接。

## 门 5 — 行为保持（仅重构 — 不可商量）
- 瘦身后的技能 + 资源驱动与原文**相同的流程和相同的输出**。
- 在原文内联内容的每一个点上，正文现在都在正确的时间到达正确的指针。
- 没有丢弃，没有重复。拿不准时，把内容留在正文。

## 门 6 — 独立评审
对新手技能跑 `code-reviewer` 子代理（Qoder 中用 Agent 工具的 CodeReview 子代理或 create-subagent 创建的自定义子代理；Claude Code 下也可用原生的 `skill-reviewer`，如果可用），对描述质量、组织结构和渐进披露做一次新鲜视角的检查。应用它高置信度的发现；忽略噪声。

## 门 7 — 触发器测试，然后真实演练
- **用户调用：** 确认 `/<name>` 出现并能跑。
- **AI 助手调用：** 用技能领域内的一个任务（使用其中一个触发器短语）描述，确认技能自动加载。如果没加载，强化 `description` 触发器并重试。
- **在真实工作上端到端演练它**——不要停在"它加载了"。真实运行会暴露加载检查永远不会暴露的问题。把你学到的折回去。

## 完成
所有门通过。对重构，**门 5 不可商量**——改变输出的重构是回归。
