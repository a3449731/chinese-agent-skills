# 系统评审（System Review）

对实现在多大程度上遵循了计划进行元层面的分析，并识别流程改进。

## 目的

**系统评审不是代码评审。** 你不是在代码里找 bug——你是在流程里找 bug。

**你的工作：**

- 分析计划遵循度和偏离模式
- 识别哪些偏离是合理的 vs 有问题的
- 提出能预防未来问题的流程改进
- 建议对 AI 层资产的更新（CLAUDE.md、计划模板、技能）

**理念：**

- 好的偏离揭示计划的局限 → 改进规划
- 坏的偏离揭示不清晰的需求 → 改进沟通
- 反复出现的问题揭示缺失的自动化 → 创建技能

## 上下文与输入

你将分析四个关键产物：

**计划技能（Plan Skill）：**
读取它来理解规划流程，以及什么指令指导计划创建。
`piv-plan-implementation` 技能（已安装于个人技能库）

**生成的计划（Generated Plan）：**
读取它来理解 AI 助手本**应该**做什么。
计划文件：$plan

**执行技能（Execute Skill）：**
读取它来理解执行流程，以及什么指令指导实现。
`piv-implement` 技能（已安装于个人技能库）

**实现报告（Execution Report）：**
读取它来理解 AI 助手**实际**做了什么、为什么。
实现报告：$report

## 分析工作流

### 第 1 步：理解计划的方法

读取生成的计划（$plan）并提取：

- 计划了哪些功能？
- 指定了什么架构？
- 定义了哪些验证步骤？
- 引用了哪些模式？

### 第 2 步：理解实际的实现

读取实现报告（$report）并提取：

- 实现了什么？
- 什么偏离了计划？
- 遇到了什么挑战？
- 跳过了什么、为什么？

### 第 3 步：对每条偏离分类

对实现报告中识别出的每条偏离，归类为：

**好的偏离 ✅**（合理的）：

- 计划假设了代码库里不存在的东西
- 实现过程中发现了更好的模式
- 需要性能优化
- 发现了需要不同方法的安全问题

**坏的偏离 ❌**（有问题的）：

- 无视计划中的明确约束
- 创建新架构而不是遵循现有模式
- 走会引入技术债的捷径
- 误解了需求

### 第 4 步：追溯根因

对每个有问题的偏离，识别根因：

- 计划不清楚吗，哪里、为什么？
- 上下文缺失吗，哪里、为什么？
- 验证缺失吗，哪里、为什么？
- 手动步骤重复了吗，哪里、为什么？

### 第 5 步：生成流程改进

基于跨偏离的模式，建议：

- **CLAUDE.md 更新：** 要记录的通用模式或反模式
- **计划技能更新：** 需要澄清的指令或缺失的步骤
- **新技能：** 应该被自动化的手动流程
- **验证补充：** 能更早抓住问题的检查

## 输出格式

把你的分析保存到：`docs/ai/system-reviews/[feature-name]-review.md`

### 报告结构：

#### 元信息

- 评审的计划：[指向 $plan 的路径]
- 实现报告：[指向 $report 的路径]
- 日期：[当前日期]

#### 总体一致性评分：\_\_/10

评分指南：

- 10：完美遵循，所有偏离都合理
- 7-9：轻微但合理的偏离
- 4-6：合理与有问题的偏离混杂
- 1-3：严重的有问题偏离

#### 偏离分析

对实现报告中的每条偏离：

```yaml
divergence: [改了什么]
planned: [计划规定的内容]
actual: [实际实现的内容]
reason: [报告里 AI 助手陈述的原因]
classification: good ✅ | bad ❌
justified: yes/no
root_cause: [计划不清楚 | 上下文缺失 | 等]
```

#### 模式遵循度（Pattern Compliance）

评估对已记录模式的遵循：

- [ ] 遵循了代码库架构
- [ ] 使用了已记录的模式（来自 CLAUDE.md）
- [ ] 正确应用了测试模式
- [ ] 满足了验证要求

#### 系统改进行动

基于分析，推荐具体行动：

**更新 CLAUDE.md：**

- [ ] 记录实现中发现的 [模式 X]
- [ ] 为 [Y] 添加反模式警告
- [ ] 澄清 [技术约束 Z]

**更新计划技能（$plan）：**

- [ ] 为 [缺失步骤] 添加指令
- [ ] 澄清 [含糊指令]
- [ ] 为 [X] 添加验证要求

**创建新技能：**

- [ ] 为 [重复 3 次以上的手动流程] 建一个新技能

**更新执行技能：**

- [ ] 向执行检查清单添加 [验证步骤]

#### 关键收获（Key Learnings）

**什么做得好：**

- [顺利推进的具体事项]

**什么需要改进：**

- [识别出的具体流程缺口]

**为下次实现：**

- [要尝试的具体改进]

## 重要

- **要具体：** 不要说"计划不清楚"——要说"计划没有指明用哪个认证模式"
- **聚焦模式：** 一次性问题不可操作。寻找重复出现的问题。
- **行动导向：** 每条发现都应有具体的资产更新建议
- **建议改进：** 不要只分析——实际写出要加到 CLAUDE.md 或技能里的文字
