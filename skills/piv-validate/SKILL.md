# 验证（Validate）

运行本项目拥有的每一项检查，并给出一个总体的 PASS/FAIL 结论。

> ## ⚠️ 先把它变成你自己的
>
> **这个技能是模板。下面的命令列表只是占位符——请替换成*你的*项目实际使用的命令。** 这正是自定义检查器的意义所在：它是唯一不能通用的技能，因为它包装的是你技术栈的 CLI。
>
> 在 `package.json` scripts、`pyproject.toml`、`Makefile`、`justfile`、`docker-compose.yml`、你的 CI 工作流或 README 中找到你的真实命令——然后删除这些并粘贴你的。
>
> **有两件事必须做对，否则检查器会在不知不觉中撒谎：**
> 1. **工作目录。** 许多工具只从当前目录发现它们的配置。如果你的配置在 `backend/pyproject.toml` 中，命令是 `cd backend && uv run pytest`，而不是从仓库根目录运行 `uv run pytest`。
> 2. **跨平台。** 如果团队中有人在 Windows 上，避免 POSIX 专属写法——`lsof`、`python3`、后台然后 `kill` 是常见的罪魁祸首。

按顺序运行检查。失败后继续运行，让报告覆盖全貌，并捕获任何失败命令的输出。

## 5. 可选 — 实时冒烟测试


优先在第二个 shell 中启动服务器，而不是在技能内部后台运行再杀掉——"后台再 kill"的写法不可移植。

## 6. 汇总报告

每项检查用 ✅ 或 ❌ 报告，然后是总体结论：

- 每项检查一行
- **总体：PASS 或 FAIL**

对每个 ❌，附上失败的命令和相关输出。本技能只负责报告，不要在这里修复任何东西——修复是单独的一步。

## 备注

- 让这个技能保持快速。它在每次提交前运行；如果某一步变慢，那是修复慢步骤的信号，而不是把它从检查器中删掉的信号。
- 一个永远不会失败的检查器毫无价值。命令接入之后，故意弄坏一处，确认本技能能报出 ❌。
