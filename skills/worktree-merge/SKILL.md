# Worktree Merge

通过一条一次性中转集成分支，把**任意数量**的特性分支集成进你的工作分支——直到每个分支都合并且整个套件通过，什么都不会落到主线上。验证命令**从仓库检测**，绝不假设。

## 执行环境（Qoder / Cursor）

git worktree 与合并命令是纯 git 功能，跨工具通用。在 Qoder 中，所有命令通过 **Bash 工具（终端）** 执行；在 Cursor 中通过内置终端执行。

## 输入

`$ARGUMENTS` 是要集成的分支列表。

- **少于两个** → 问要集成哪些分支。不要猜。
- **两个或更多** → 按给定顺序集成它们。

## 只检测一次验证命令

找到能证明这个项目能工作的命令，偏好 **CI 已经跑的那个**：读取 `.github/workflows/*`、`Makefile`、或 manifest 的 test/lint 脚本，并复用那些确切的命令（测试运行器、类型检查器、linter）。不要硬编码 `pytest`/`mypy`/`pyright`——用这个仓库实际用的。

## 步骤

1. **前置条件。** 确认你在仓库根目录，不在 `worktrees/` 里面（`[[ $(pwd) =~ /worktrees/ ]]` → 报错）。保存当前分支。验证列表里每个分支都存在（`git rev-parse --verify <branch>`）。任何检查失败就用清晰的消息提前中止。

2. **创建一条集成分支**，从当前分支出发，以这组分支命名（例如 `integration-<first>`，有好几个就加短后缀——保持文件系统安全）。这里是测试合并的地方；主线直到最后都不动。

3. **按顺序合并每个分支**，`--no-ff`。**每次**合并后，运行检测出的**测试**命令，这样破坏能定位到造成它的分支。
   - **冲突时：** 停下，点名冲突的分支和文件，给出解决步骤（解决 → `git add` → `git commit` → 重新运行本技能）。不要尝试自动解决。
   - **测试失败时：** 停下，报告哪些测试失败，给出回滚命令（`git checkout <original>` → `git branch -D <integration>`）。

4. **全部合并后做完整验证**：运行项目完整的检测套件（测试 + 类型检查 + lint）。任何失败 → 报告并回滚；什么都不准红着上主线。

5. **把集成分支合并进原分支**（`--no-ff`），然后删除集成分支。

6. **用问题工具（AskUserQuestion）询问清理方式**：移除 N 个 worktree 并删除它们的特性分支，或保留它们。选择移除时，对每个分支：`git worktree remove worktrees/<branch>` 和 `git branch -d <branch>`。

## 报告

- **成功：** 用到的集成分支、每个分支的合并（带合并后的测试结果）、完整验证结果、合并进 `<original>`、以及清理状态（worktrees 保留或移除；保留时给出手动清理命令）。
- **失败：** 失败的步骤和分支、当前分支状态、确切的回滚命令（`git checkout <original>` → `git branch -D <integration>`），以及修好后如何继续（用同样的分支列表重新运行）。

## 备注

- `--no-ff` 保留每个特性分支的历史。
- 集成分支是一次性的——只有每个合并都完成且完整套件通过后，原分支才会移动。
- 团队协作时偏好每个分支开一个 PR；本技能用于你拥有合并权时的快速本地集成。
