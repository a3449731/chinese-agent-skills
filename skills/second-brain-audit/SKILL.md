# 第二大脑审计（Second Brain Audit）

笔记以特定的方式腐烂。没有东西损坏，也没有东西丢失：一个事实只是不再为真，笔记继续这么说，而没有任何东西举手示意。

原因几乎总是一样的。**写入路径只能追加。** 新信息到达，成为旧行下面的一行新内容——这对某些事实是正确的，对另一些则是毁灭性的。

## 核心思想

每条存储的事实都是两种之一。

| | 含义 | 正确的更新 |
|---|---|---|
| **状态（State）** | 一个当前值，而且它会**变化** | **替换**它 |
| **事件（Event）** | 一件带时间戳的、**发生过**的事 | **追加**它 |

价格、状态、所有者、截止日期：状态。付款、签名、决定、学到的教训：事件。

更新规则**正好相反**。替换事件会摧毁历史。追加状态会为一个问题创造出两个答案，且没有任何标记说明哪个是当前的——而过时的那份通常位于文件更靠上的位置，所以会先被读到。

**承载这条规则的是结构，不是指令。** 让模型——或人——记得去更新旧条目，会安静而持续地失败。给页面两个章节，规则就随事实落在哪里而自然成立。

## 阶段 1：确定形态

**不要假设有 wiki、保管库或页面。** 大多数情况一样都没有。先看实际存在什么，因为它既改变审计能看到的，也改变修复应该是什么。

| 形态 | 看起来像 | 状态应该住在哪里 |
|---|---|---|
| **每主题一页** | `clients/acme.md`、`projects/x.md` | 每页两个章节 |
| **一个大文件** | 单个 `notes.md` 或 `CLAUDE.md` | 顶部一个 `## Current State` 块 |
| **只有每日笔记** | `2026-06-01.md`，没有别的 | **没有可转换的东西。** 状态层完全缺失 |
| **不是 markdown** | Notion、Apple Notes、聊天助手的记忆 | 思想仍然适用；工具不适用 |

然后确定两件事：

1. **笔记住在哪里。** 一个 markdown 文件夹，供扫描用。
2. **AI 助手每次会话读什么。** `CLAUDE.md`、`MEMORY.md`、系统提示词文件——任何自动加载的东西。这比其他任何东西都重要：档案里的过时事实无害，同一个事实在常驻加载文件里就是 bug。如果用户不知道，说出来，并且没有它也要继续运行。

只有每日笔记是最值得点名说出来的情况。带日期的笔记是**事件日志**，而事件本来就该累积；它们没有任何坏掉的地方。缺失的是任何说出*现在*什么为真的地方。告诉某人重组他们的日记会是积极的错误。

## 阶段 2：审计常驻加载的表面

**这是对每个第二大脑都有效的部分**，任何工具、任何领域、有没有脚本都行。总是运行它，即使扫描已经发现了很多。

AI 助手每次会话读的东西很小：这正是它能常驻加载的原因。所以它可以被完整读取、逐条主张地检查。

1. **完整读取那个表面。** 常驻加载的文件，或一个大文件的顶部，或置顶的页面。全部。
2. **提取每条状态形状的主张。** 任何以当前事实措辞表达的东西：状态、所有者、费率、版本、截止日期、"currently"、"we use"、"lives at"。忽略任何以事件措辞表达的，因为事件保持为真。
3. **对每条主张，去笔记里任何地方找最新鲜的证据。** Grep 主题。读取提到它的最新文件。
4. **把每条主张分进三堆：**
   - **已确认（Confirmed）。** 细节一致。
   - **被反驳（Contradicted）。** 有更新的东西不一致。这是腐烂，是头条。
   - **无支持（Unsupported）。** 没有任何东西支持它。通常是这个主张曾经为真、证据从未被写下——这值得大声说出来。

十到三十条主张很正常，而且只是几分钟的阅读。一个没有钱的研究保管库、一个个人 wiki、一个 Notion 工作区：都能这样审计，而且都不是脚本能审的。

先报告被反驳的那堆，再报告无支持的那堆。两者都是发现。

## 阶段 3：如果笔记适合，运行扫描

一个加速器，不是审计本身。它适用于事实带货币价值的 markdown 文件夹，而且比阅读快得多地发现跨文件的分歧。否则跳过；阶段 2 已经做了工作。

```bash
python <skill>/scripts/audit.py <notes-dir> \
    --always-loaded MEMORY.md --always-loaded CLAUDE.md
```

传 `--subject "Acme Corp"` 按名字追踪具名主题，传 `--json` 获取结构化输出。脚本只读；从不写。

**零不等于健康证明。** 数值是它唯一能在不猜测的情况下比较的东西，所以没有钱的笔记对它来说基本不可见。当它知道自己瞎了时会打印 COVERAGE WARNING。把这个警告读出来，而不是报告"未发现问题"。

**为什么需要脚本：** 计数必须两次一致。让模型统计 600 条要点，它今天会返回一个自信的数字、明天又是一个不同的——这正是本技能要修的那类失败。脚本计数。AI 助手判断。

## 阶段 4：读两者都看不见的东西

打开几个被标记的页面，寻找任何正则都抓不到的：

- **生命周期冲突。** 一个页面说"下周上线"，而三个月前的日志条目记录项目被取消了。没有数字不一致，所以什么都不会被标记，而它完全错了。
- **从未被写下的事实。** 错误答案最常见的成因不是组织得差；而是真实值只存在于一次对话或一条每日笔记里。重组够不到它。坦率说出来，而不是暗示重组会有帮助。
- **绝不能动的页面。** 检查清单、参考清单、打包清单。它们故意是清单。转换一个会摧毁使它有用的东西，而且每项结构检查仍然通过。

## 阶段 5：报告

以单一最有害的发现开头，而不是工具输出的摘要：

> Acme 付多少钱有三个不同答案，而最旧的那个在 AI 助手每次会话都读的文件里。

在 AI 助手已经跑在这些笔记上的地方，**演示它**。问一个笔记应该能回答的问题，把回答读出来。看着助手自信地返回一个三月就不再为真的数字，比任何报告都更有冲击力。指出常见的情况——它*勤勉却仍然错*：它检查一个页面，警告另一个文件看起来陈旧，却仍然错过真实值，因为那个值从未被提升到任何持久的地方。

## 阶段 6：修一处

绝不批量转换，也绝不转换用户没同意的页面。修复单一最糟的*位置*，取决于阶段 1 找到的形态：

- **每主题一页** → 给那一页下面的两个章节。
- **一个大文件** → 顶部加一个 `## Current State` 块，其他一切留在它下面。不建新文件，不建文件夹结构。
- **只有每日笔记** → 创建**一个**保存当前值的文件，每篇日志条目原样保留。日志本来就是对的。
- **不是 markdown** → 不重组任何东西。解释当前值应该住在他们已在用的工具里的哪里，到此为止。

下面的形态是每主题一页的版本；把同样的两个思想适配到其他形态。每种情况下必须为真的只有一点：**一个地方说出现在什么为真，而且它是被替换而不是被追加。**

```markdown
## Current State
<!-- 每个主题一条。带日期。更新时 REPLACE（替换），绝不 append（追加）。-->

- **Retainer（顾问费）** (2026-08-01)：$3,200/月，续约到 2027 年 2 月
- **主要联系人** (2026-05-02)：Curtis Ilo

## Log
<!-- 只追加。绝不编辑或删除条目。-->

- (2026-04-30) 交付并付款，$21,000
- (2026-05-02) 顾问费从 $2,800/月开始
- (2026-06-15) 增加了回复起草，顾问费至 $3,200/月
```

转换规则，按重要性排序：

1. **不丢任何东西。** 每条现有行都落到两个章节之一，逐字。这是归类，不是重写。润色措辞正是信息在没人注意的情况下消失的方式。
2. **Current State 里每个主题一条。** 两行描述同一个当前值的地方，更新的胜出，更旧的移入 Log。顺序不清楚的地方，问。绝不猜。
3. **给每条 Current State 条目标日期。** 缺失日期就问，或从文件历史取。一个没有日期的当前值比过时值好不了多少。
4. **绝不合并两个只是看起来相似的主题。** "Acme（五月）"和"Acme Corp 续约"可能是真正不同的东西。重复条目是便宜的失误；错误的合并摧毁信息。报告近似命中的情况，让用户决定。
5. **展示 diff 并获得批准**再写入。

之后重新问早先的问题，让正确的答案可见。同样的笔记，同样的 AI 助手，一个页面被重组。

## 阶段 7：改变写入路径

这个阶段决定审计是否值得。转换页面修复今天；改变事实如何被写入才是阻止复发的东西。

在指示 AI 助手的任何文件里添加（`CLAUDE.md`、`AGENTS.md`、系统提示词）：

```markdown
## 写入这些笔记

每条事实都是状态或事件。

- **状态**（一个会变化的当前值：价格、状态、所有者、日期）：
  在 `## Current State` 里找到匹配行并 REPLACE 它。永远标日期。
  绝不为同一主题添加第二行。
- **事件**（一件发生过的事）：追加到 `## Log`。绝不编辑或删除
  现有 Log 条目。

拿不准时，追加到 Log 并说明。缺失的状态更新可恢复；
被重写的历史不可恢复。
```

然后说出诚实的部分：这条指令大部分时候会被遵循，不是所有时候。任何必须每次发生的事都需要机制。两个比指令更值的便宜机制：

- 按计划重新运行这次审计，观察计数是否攀升。
- 事后用脚本盖日期戳，而不是索要它们。

## 诚实地设定预期

单独的重组常常比人们预期的更少移动数字。当它不移动时，原因通常是正确的事实从未被捕获，而任何数量的重组都够不到一个没人写下的事实。在适用时说这个。审计的真正价值是识别*两个问题中的哪一个*在起作用。
